## 2 品牌与产品愿景

“墟”取意于“归墟”。项目借《山海经》中万物流转、终有所归的意象，表达知识的另一种轮回：资料被记录、分享和修订，又在下一位读者心中重新生长。

产品愿景是建立一个开放、可迁移、低维护成本的课程知识汇流地：

1. 内容不被某个编辑器、平台账号或私有数据库锁定。
2. 新增课程只需要整理文件，不需要修改页面代码。
3. 阅读、搜索、打印和下载尽量在访客浏览器完成。
4. 公开协作依托 GitHub，不为了评论或投稿建立后端。
5. 平台代码保持足够简单，使其他人能借助 AI 理解、复制和改造。

资料库目前侧重管理学院课程，重在把已有资料按课程和原文件夹层级整理得更细，不以覆盖全校为目标。需要其他学院或更广的厦大课程资料时，资料页应明确推荐 [鹭岛书阁](https://xmu.vintces.icu/)（[项目仓库](https://github.com/vintcessun/XMUHub)）作为互补入口；XU 不复制对方的资料或宣称与其存在官方合作。

## 3 背景与问题

课程资料常见于 Word、PDF、截图、聊天记录和零散 Markdown，容易出现：

- 目录层级混乱，新增内容后无法自动汇总；
- 公式、表格和中文排版在不同工具中表现不一致；
- PDF 和图片难以继续编辑，搜索能力弱；
- 分享依赖网盘、登录或临时链接；
- 动态平台需要服务器、数据库、备案和持续费用；
- 服务端批量生成 PDF 或 ZIP 会消耗计算、内存和存储；
- 第三方 CDN 或插件失效后，核心阅读能力随之失效。

XU 使用 Git 管理原文件，在构建阶段生成静态清单，再由浏览器按需完成阅读和下载，从源头减少这些问题。

## 4 产品目标

### 4.1 核心目标

1. 通过文件夹层级表达分类、课程和章节。
2. 支持 Markdown 与完整 HTML 两条发布通道。
3. 自动生成课程目录、搜索索引和下载清单。
4. 统一渲染 Markdown 标题、三线表、公式、代码、引用、提示框、重点高亮和带图注图片。
5. 支持树状文章目录、当前章节跟随、目录筛选与折叠、锚点、面包屑、前后篇和移动端导航。
6. 支持复制原文、单文件下载、课程级原文件批量下载。
7. 使用浏览器原生打印生成 A4/PDF。
8. 不运行常驻业务服务器，不保存访客数据。
9. 所有核心运行时依赖随站点发布，不依赖第三方 CDN。
10. 提交到 `main` 后自动检查、构建并部署。

### 4.2 成功标准

- 新增合规内容后，不修改前端代码也能自动出现在目录和搜索中。
- 首页不请求全部文章正文。
- Markdown 公式经过一次解析即可正确显示。
- 普通数据表默认呈现三线表且移动端可局部滚动。
- 打印内容不出现导航、按钮或“跳到正文”等网页控件。
- 批量下载不在服务器生成 ZIP 或临时文件。
- 站点在没有数据库和业务后端的情况下完成核心体验。
- 构建失败能明确指出存在问题的内容文件。

## 5 非目标

当前版本不实现：

- 用户注册、登录、权限和个人中心；
- 在线协同编辑或所见即所得编辑器；
- 服务端评论、点赞、收藏或推荐系统；
- 服务端数据库与动态搜索接口；
- 服务端生成 PDF、Word 或 ZIP；
- 高保真 DOCX 导出；
- 支付系统或付费内容控制；
- 自动审核 AI 生成内容；
- 中国大陆访问速度和可用性的绝对承诺。

交流、缺陷和合作请求统一使用 GitHub Issues 或 Pull Requests。

## 6 用户与核心场景

### 6.1 内容维护者

- 在本地或 GitHub 分支中编辑课程文件；
- 使用 Markdown 保存可继续维护的知识；
- 对特殊专题直接提供完整 HTML；
- 运行构建检查并提交；
- 通过 Cloudflare 自动部署发布。

### 6.2 普通访客

- 从首页或左侧目录进入课程；
- 搜索课程名称、章节和正文；
- 阅读公式、三线表、图片和代码；
- 复制或下载单篇原文件；
- 打印为 A4/PDF。

### 6.3 批量下载者

- 在课程右侧“⋯”打开原文件下载面板；
- 在同一分类内选择一门或多门课程；
- 查看系统根据文件数和体积生成的批次；
- 选择本地目录并由浏览器流式保存原文件；
- 在不支持目录 API 的浏览器中逐项下载。

### 6.4 合作者与复用者

- Fork 仓库并替换 `content/`；
- 根据 README 理解目录、渲染和部署；
- 使用 AI 辅助整理 Markdown、生成课程元数据或修改主题；
- 通过 Pull Request 向原项目贡献课程或平台改进。

### 6.5 资料访客

- 从 RESOURCE 进入，按原文件夹层级或文件名查找资料；
- 按需预览 PDF、TXT 等格式，或下载 GitHub Release 中的原文件；
- GitHub 可直连时直接下载，无法直连时自动使用经过实测和校验的加速线路；
- 从预览返回时保留搜索词、目录展开状态和浏览位置；
- 找不到目标课程时，使用资料页的鹭岛书阁链接继续查找。

## 7 信息架构与首页顺序

首页先展示品牌与 NOTE / RESOURCE 两个入口，再展示品牌故事、开源协作和支持信息。NOTE 保留左右目录的连续阅读布局；RESOURCE 使用独立的无侧栏资料页，顶部提供搜索，下面按文件夹层级浏览。资料页的说明横幅明确推荐鹭岛书阁，以补足 XU 跨学院覆盖有限的范围。

阅读页由以下部分组成：

- 顶部品牌栏；
- 左侧课程目录；
- 中部文章与操作栏；
- 右侧文章目录；
- 面包屑与前后篇导航；
- 移动端折叠目录。

## 8 内容模型

### 8.1 目录即数据

`content/` 是 NOTE 的课程内容入口。RESOURCE 的逻辑目录由本地 `release-staging/` 扫描生成 `release-resources.json`；GitHub Release 只存扁平的单个附件，不承载文件夹层级。部署环境没有暂存目录时使用已提交的清单，不从 GitHub API 动态扫描仓库。

推荐结构：

```text
content/
├── 分类名称/
│   ├── 课程 A/
│   │   ├── course.json
│   │   ├── 01-第一章.md
│   │   ├── 02-专题.html
│   │   └── assets/
│   └── 课程 B/
└── 自我介绍/
    └── 知识库平台_PRD.md
```

若课程直接位于 `content/` 第一层，也可以省略外层分类。

### 8.2 course.json

课程元数据文件为可选项：

```json
{
  "name": "财务管理 A",
  "description": "课程复习笔记与例题",
  "order": 10
}
```

- `name`：首页与目录显示名称；
- `description`：课程卡片说明；
- `order`：课程排序，数值越小越靠前。

未提供时，系统使用目录名和默认顺序。

### 8.3 Markdown 规则

- 每篇文章必须且只能有一个一级标题。
- 标题层级不得跳级。
- 行内公式使用 `$...$`。
- 独立公式使用 `$$...$$`。
- 表格使用标准 Markdown 表格语法。
- Obsidian 风格提示框使用 `> [!类型] 标题`，重点高亮使用 `==内容==`；两者应克制使用。
- 图片可用 Markdown 标题填写图注，例如 `![替代文字](https://example.com/image.webp "图 1｜来源与许可")`。
- 图片必须具有替代文本。
- 外部链接必须使用 HTTPS。
- 文件名前可加两位或三位序号控制排序。
- 不使用截图替代可编辑的文字、公式和数据表。

AI 从 PPT、PDF、Word 或扫描资料提炼课程笔记时，必须先阅读 `content/课件与PDF笔记提炼规范.md`，并结合目标课程已有笔记统一术语、结构、公式解释和来源记录。该规范位于内容根目录，是 AI 的强制工作说明，也可供维护者人工复核；它不要求把全部 Obsidian 专有语法引入 XU。

Markdown 可选 YAML 风格头信息，当前识别：

- `title`；
- `description`；
- `order`；
- `audience`：设为 `ai` 时代表内容主要供 AI 执行任务前读取；文件仍可作为公开规范被人工查看。

直接位于 `content/` 根目录的 Markdown 或 HTML 不归入虚构的“未分类”课程，而是在 NOTE 目录和笔记首页作为根级文章直接显示。它仍参与全文搜索和单篇原文下载，但不形成课程级下载文件夹。

### 8.4 完整 HTML 规则

HTML 文件直接作为独立页面发布，不套用 Markdown 阅读模板。

构建阶段禁止：

- 自定义脚本；
- 内联事件属性；
- `javascript:` 链接；
- iframe、object、embed 和 form。

如确需公共脚本，只能引用 `/static/html-tools.js`。

### 8.5 附件归属

课程目录内的全部普通文件都会进入该课程的原文件下载清单。符号链接不进入清单。首页品牌与支持素材放在根目录 `支持/`，不作为课程附件。

## 9 总体架构

```text
[内容与代码]
GitHub main
├── content/ 原文件
├── src/ 浏览器应用
├── scripts/ 构建程序
└── public/ 静态配置
        │ push
        ▼
[质量检查]
GitHub Actions
└── npm ci → npm run build
        │
        ▼
[Cloudflare Git 构建]
npm run build
├── 校验内容
├── 生成静态清单
└── Vite 打包
        │
        ▼
npx wrangler deploy
        │
        ▼
[Workers Static Assets]
静态缓存与分发
        │
        ▼
[访客浏览器]
按需阅读 / 搜索 / 打印
├── GitHub 可直连 → Release 原地址下载
├── GitHub 不可直连 → 已校验加速线路
└── PDF/TXT 预览兜底 → Worker 受限同源入口
```

系统没有常驻业务服务器、数据库、对象存储写入任务或后台队列。附件只发布一份到 GitHub Release。浏览器读取 `public/release-mirrors.json`，检测 GitHub 直连能力，并对基础线路和在线更新名单中的候选线路进行实测；镜像只有在真实探测附件的大小与 SHA-256 都一致时才进入排序。Cloudflare Worker 仅为清单中已发布的 PDF/TXT 提供最终同源预览兜底，不将全部资料打包进静态站点。

## 10 构建阶段

`scripts/build-content.mjs` 负责：

1. 递归扫描 `content/`；
2. 识别 Markdown、HTML 与课程元数据；
3. 校验标题层级、图片替代文本和 HTTPS 链接；
4. 校验 HTML 中的危险能力；
5. 将原始内容复制到 `public/content/`；
6. 生成 `public/generated/catalog.json`；
7. 生成 `public/generated/search-index.json`；
8. 生成 `public/generated/downloads.json`；
9. 输出课程数、文档数和格式统计；
10. 严重错误时以非零状态终止构建。

三份清单分别承担：

| 清单 | 用途 |
|---|---|
| `catalog.json` | 课程导航、首页卡片、文档顺序和路由 |
| `search-index.json` | 浏览器静态全文搜索 |
| `downloads.json` | 课程、原文件路径、文件大小和下载分批 |

这些文件是构建产物，不提交 Git。

## 11 浏览器阅读流程

### 11.1 首页

- 首次只加载站点外壳、样式和 `catalog.json`；
- 搜索框第一次获得焦点时才加载搜索索引；
- 支持区图片使用延迟加载；
- 不读取全部文章正文。

### 11.2 Markdown

1. 根据哈希路由定位文档；
2. 请求单篇原始 Markdown；
3. 去除头信息；
4. Marked 与 marked-katex-extension 一次解析正文和公式；
5. DOMPurify 清理生成的 HTML；
6. 将受支持的提示框、图片图注等轻量语义增强为阅读组件；
7. 为标题分配稳定页面内锚点；
8. 为表格增加横向滚动容器；
9. 生成右侧文章目录。

文章目录按照二至四级标题建立树状层级。桌面端固定显示在右侧；窄窗口与手机端继续并入左侧栏，通过“笔记目录 / 本文目录”标签切换。阅读滚动时高亮当前章节，长目录可按标题筛选，也可单独折叠分支或一键展开、收起。目录点击仍保留平滑跳转，标签页阅读位置恢复仍使用无动画的立即定位。

每个已打开标签分别保存滚动位置。用户切换回已有标签时必须在新文章绘制前后直接恢复该位置；目录和书签跳转可以保留平滑动画，但标签恢复不得从文章开头播放滚动过程。

公式不再经过“先保护、解析正文、再恢复公式”的多阶段流程。

### 11.3 完整 HTML

HTML 文档直接打开其静态路径，因此保留作者的完整页面设计。其安全边界主要由构建阶段校验、CSP 和静态托管共同保证。

## 12 渲染规范

### 12.1 公式

- 使用 KaTeX；
- 由 marked-katex-extension 在同一次 Markdown 解析中识别；
- 同时输出 HTML 与 MathML；
- `throwOnError` 关闭，异常公式保留可见提示；
- 字体随构建产物自托管；
- 独立公式可横向滚动且打印时尽量不拆页。

### 12.2 表格

- 顶线、表头分隔线、底线构成三线表；
- 默认无竖线；
- 网页端超宽表格仅在自身容器横向滚动；
- 打印时移除滚动裁切；
- 长表格分页后重复表头；
- 单行尽量不跨页。

### 12.3 提示框、重点与图片

- 支持 `note`、`summary`、`info`、`todo`、`tip`、`important`、`success`、`question`、`warning`、`failure`、`danger`、`bug`、`example` 和 `quote` 提示框，并为常见别名归一化；
- 支持 `==内容==` 形式的行内重点高亮和 GFM 任务清单；
- 仅包含图片的段落会转换为语义化 `figure`，图片 Markdown 标题转换为 `figcaption`；
- 提示框、图注和高亮同时用于在线 NOTE 与“我的资源”中的本地 Markdown；
- 只借鉴适合课程阅读的 Obsidian 语法，不实现双链、关系图谱、插件或编辑器能力；
- 新语义不得破坏普通引用、公式、表格、目录和打印。

### 12.4 安全清理

Markdown 生成 HTML 后由 DOMPurify 处理：

- 保留常规 HTML 与 MathML；
- 禁止 script、iframe、object、embed 和 form；
- 禁止常见内联事件属性。

## 13 搜索

- 索引在构建阶段生成；
- 覆盖标题、课程路径、说明和正文；
- 支持中文关键词和多个空格分隔词；
- 所有检索词都必须在同一条目中匹配；
- 最多展示 12 条结果；
- 浏览器不会为建立索引而逐篇请求 Markdown。

当前搜索为轻量字符串包含匹配，不提供分词、拼音、模糊搜索和相关性评分。

## 14 原文件下载

### 14.1 单篇

阅读页允许：

- 复制当前原文；
- 下载当前原始 Markdown；
- 独立 HTML 使用其静态原文件。

### 14.2 课程批量下载

设计原则是“服务器只提供静态原文件，下载负担由访客浏览器承担”。

- 入口位于课程标签右侧“⋯”；
- 可在同一分类内选择多门课程；
- 下载原始 MD、HTML、图片和附件；
- 不下载转化后的阅读 HTML；
- 不批量打印 PDF；
- 不在服务器或仓库生成 ZIP；
- 保留 `content/` 内的目录结构。

默认批次上限：

| 限制 | 数值 |
|---|---|
| 每批文件数 | 50 |
| 每批总体积 | 100 MiB |
| 桌面并发 | 3 |
| 移动端并发 | 2 |
| 单文件失败重试 | 1 次 |

分批算法优先保持课程完整；若多门课程可共同放入一个批次则自动组合；只有单门课程自身超过限制时才按文件拆分。

Chrome 和 Edge 使用 File System Access API 让用户选择保存目录，响应体通过流直接写盘。其他浏览器显示原始文件链接作为回退。

### 14.3 RESOURCE 附件线路

- Release 附件只上传到 GitHub，不在 Gitee 重复保存一套大文件；
- 浏览器先检测 GitHub 是否可直连，开着代理的访客直接使用 GitHub 原地址；
- 无法直连时，从随站点维护的基础线路和在线更新候选名单中筛选可用线路；
- 镜像探测必须校验真实附件的文件大小和 SHA-256，不能只判断首页是否打开；
- PDF/TXT 预览按“直连或加速线路 → 其他可用线路 → Worker 同源入口”的顺序故障切换；
- 未经完整校验的 GitHub 直连可达结果只在当前页面使用，不写入长期缓存；
- 在线候选名单只提供待测地址，不能直接取得信任。

## 15 打印与 PDF

打印不使用 Paged.js，也不使用服务端渲染。

点击“A4 / PDF”后：

1. 按需加载 `page.js` 与 `print.css`；
2. 等待字体完成；
3. 使用浏览器原生 `window.print()`；
4. 用户在系统打印对话框中保存 PDF。

打印规则：

- A4 页面与统一页边距；
- 页面底部页码；
- 隐藏顶部导航、侧栏、文章操作按钮和无障碍跳转入口；
- 标题尽量不与后续正文分离；
- 公式、图片、代码块和引用尽量不跨页；
- 长表格允许分页并重复表头。

最新版 Edge 和 Chrome 为推荐环境。不同浏览器、系统字体和打印驱动可能产生分页差异。

## 16 轻量化与性能策略

### 16.1 不使用的能力

- React、Vue 等运行时框架；
- Paged.js；
- JSZip；
- 通用服务端业务 API（仅保留受限的 PDF/TXT 预览入口）；
- 数据库；
- 运行时第三方 CDN；
- 服务端浏览器渲染；
- 服务端压缩与临时文件。

### 16.2 运行时依赖

| 依赖 | 作用 |
|---|---|
| `marked` | Markdown 解析 |
| `marked-katex-extension` | 在同一解析流程识别公式 |
| `katex` | 数学公式排版 |
| `dompurify` | HTML 安全清理 |

Vite 与 Wrangler 仅用于构建和部署。

### 16.3 加载策略

- 文章按需获取；
- 搜索索引首次搜索时获取；
- 打印代码点击按钮时获取；
- 下载代码点击“⋯”时获取；
- 支持图片滚动到附近时获取；
- 带内容指纹的构建资源长期缓存；
- 内容与生成清单使用短缓存并重新验证。
- 进入站点后在后台检测附件线路，不阻塞 NOTE 正文阅读；
- 线路排序缓存 30 分钟，经过完整校验的历史结果最多保留 7 天。
- PDF.js Worker 由 Vite 单独构建为普通 `.js` 文件，兼容不能正确识别 `.mjs` MIME 类型的静态托管平台；正式构建不发布 source map，以减少部署和手动上传体积。

## 17 安全与隐私

- CSP 限制脚本、样式、字体、连接和嵌入来源；
- 使用 `X-Content-Type-Options: nosniff`；
- 使用 `X-Frame-Options: SAMEORIGIN`；
- 禁用摄像头、麦克风和地理位置权限；
- 外部链接增加 `noopener noreferrer`；
- 外部镜像候选只接受无账号、无异常端口的公网 HTTPS 地址，并使用 `no-referrer` 请求；
- 镜像返回的附件必须通过清单记录的大小和 SHA-256 校验；
- Markdown HTML 必须清理；
- HTML 文件必须通过构建校验；
- 不采集访客个人信息；
- 不使用 Cookie、账号或数据库；
- 仓库不得保存密钥、令牌和私人资料。

支持二维码属于维护者主动公开的首页素材，不进入课程下载清单。

## 18 可访问性与兼容性

- 页面使用语义化 header、nav、main、article、aside；
- 提供“跳到正文”的键盘入口；
- 所有图片具有替代文本；
- 交互元素可用键盘操作；
- 不只使用颜色表达状态；
- 移动端使用抽屉式课程目录；
- 公式和表格允许局部横向滚动；
- 打印时隐藏无障碍跳转入口，避免覆盖正文。

完整阅读能力面向现代 Chrome、Edge、Firefox 和 Safari。目录批量写盘以支持 File System Access API 的浏览器为最佳体验。

## 19 发布、质量检查与回滚

### 19.1 标准流程

1. 修改 `content/` 或平台代码；
2. 本地运行 `npm run build`；
3. 提交到功能分支或 `main`；
4. GitHub Actions 执行干净安装与构建；
5. Cloudflare Git 构建执行相同构建命令；
6. Wrangler 部署 `dist/`；
7. 检查线上状态；
8. 出现问题时回退对应 Git 提交。

### 19.2 自动化

GitHub Actions 在以下事件运行：

- 推送到 `main`；
- Pull Request；
- 手动触发。

工作流使用 Node.js 22、`npm ci`、`npm run build`，并保存构建产物用于检查。

### 19.3 Cloudflare 配置

| 项目 | 当前值 |
|---|---|
| Worker | `xu` |
| 生产分支 | `main` |
| 构建命令 | `npm run build` |
| 部署命令 | `npx wrangler deploy` |
| 静态目录 | `dist/`；`worker/index.js` 提供受限预览入口 |
| 自定义 workers.dev 子域 | `lucifer-cgl` |

### 19.4 国内入口

国内入口为 <https://lucifer.gicp.fun/>，使用花生壳/贝锐静态托管承载本地构建后的 `dist/` 静态产物。

该入口的定位是降低中国大陆访客的网络门槛：在不要求访客配置网络代理、不新增服务器、不备案自有域名的前提下，提供一个更容易直连访问的站点。

与 Cloudflare 主站相比，它的边界如下：

- 优点：国内访问更友好，阅读、搜索、打印和 AI Assistant 均可继续使用；RESOURCE 附件还可由浏览器选择已校验的可用加速线路；
- 缺点：目前不能直接连接 GitHub 自动部署，需要维护者本地构建后手动上传 `dist/`；
- 更新节奏：Cloudflare 主站随 GitHub 推送自动更新，国内入口按维护者手动同步节奏更新，可能存在数小时到数天滞后；
- 数据边界：两者都只是静态站点，不新增后端、数据库、账号、API Key 或服务端计算任务。

国内入口与 Cloudflare 主站共用同一份附件线路配置。站点入口的托管位置和 Release 附件的下载路径是两个独立问题：前者仍由各自静态托管平台承载，后者根据访客网络在 GitHub 直连与加速线路之间选择。

两个站点入口另使用 `public/site-mirrors.json` 管理。页面加载后通过 1 像素静态图片实测线路，不读取代理软件名称、IP 或系统代理配置。Cloudflare 直连已经可用时保持原线路；从国内入口访问且主站在阈值内可达时，保留当前路径、查询参数和哈希路由转到主站；用户手动固定国内线路后不再自动跳转。因为选择逻辑需要先加载页面，它不能挽救一个完全打不开的首个入口；这种情况仍需分享国内入口、独立启动页或 DNS 层调度。

花生壳静态托管会把 `.mjs` 返回为 `application/octet-stream`，无法直接运行 PDF.js 模块 Worker。因此生产构建必须输出 `.js` Worker；不能把依赖中的原始 `.mjs` 直接复制进 `dist/assets/`。

## 21 使用 AI 复用或扩展本项目

本仓库应让 AI 能通过少量文件理解系统。建议复用者向 AI 提供：

1. 本 PRD；
2. 根目录 README；
3. `package.json`；
4. `scripts/build-content.mjs`；
5. `src/main.js`、`src/download.js` 和样式文件；
6. 一门示例课程。

若任务涉及从课件、PDF、Word 或扫描资料提炼笔记，还必须提供并优先阅读 `content/课件与PDF笔记提炼规范.md`，再读取目标课程的已有笔记。

推荐让 AI 按以下顺序工作：

1. 先解释内容模型和构建流程；
2. 列出计划修改的文件；
3. 保持纯静态边界；
4. 优先复用浏览器原生能力；
5. 避免为了单一功能引入大型依赖；
6. 修改后运行 `npm run build`；
7. 检查 Markdown、公式、表格、移动端、打印和下载回归；
8. 同步更新文档。

AI 整理课程内容时仍需人工核对：

- 事实与计算；
- 公式和符号；
- 标题层级；
- 图片版权；
- 引用来源；
- 隐私信息。

不要让 AI 直接把来源不明的大量二进制文件、依赖包、密钥或生成产物提交到仓库。

## 22 验收标准

### 22.1 内容

- 新增合规 Markdown 后自动进入目录和搜索；
- 新增完整 HTML 后可以直接打开；
- 不需要手改首页和导航；
- 错误标题层级或危险 HTML 会使构建失败。

### 22.2 阅读

- 桌面与手机无页面级横向溢出；
- 表格和长公式只在自身容器滚动；
- 所有 Markdown 表格呈现三线表；
- 受支持的提示框、`==重点高亮==`、任务清单和图片图注正确显示；
- 同一篇 Markdown 在线打开与从“我的资源”本地打开时使用相同的正文渲染规则；
- 文章目录定位当前文章内标题，不返回首页；
- 文章目录正确呈现标题父子层级，可筛选、折叠，并随正文滚动高亮当前章节；
- 窄屏的“笔记目录 / 本文目录”切换继续可用，选择标题后关闭移动端抽屉；
- 公式无明显原始 LaTeX 泄漏或解析错误。
- 切回已打开的文章标签时立即回到上次阅读位置，不出现从页首向下滑动的恢复动画。

### 22.3 下载

- 单篇原文可复制和下载；
- 多课程能按数量和体积自动分批；
- 不产生服务端 ZIP；
- 保存内容与仓库原文件字节一致；
- 保存目录保留层级；
- 不支持目录 API 时有可用回退。
- GitHub 可直连时不强制绕行镜像；
- GitHub 无法直连时至少能尝试已校验的备用线路；
- 镜像内容与 Release 清单的大小和 SHA-256 一致。

### 22.4 打印

- A4 页面、页码和正文正常；
- 导航、按钮和“跳到正文”不进入打印内容；
- 公式、图片和短表格不被明显裁切；
- 长表格分页后仍可辨认表头。

### 22.5 安全与部署

- Markdown 脚本无法执行；
- 危险 HTML 无法通过构建；
- 响应头包含 CSP 等安全策略；
- GitHub Actions 和 Cloudflare 构建均成功；
- 生产地址可读取首页、清单和原始内容。

## 23 已知限制

1. 静态全文搜索不具备复杂中文分词和模糊匹配。
2. Safari 与 Firefox 不能获得与 Chromium 相同的目录批量写盘体验。
3. PDF 分页受浏览器版本、系统字体和打印设置影响。
4. 大图片仍会增加 Git 历史和首次查看该图片时的流量。
5. Git 集成每次推送都会重新构建，不是真正的增量构建。
6. workers.dev 在不同网络环境中的速度需要实际测试。
7. 极大课程库未来可能触及构建文件数量或仓库体积边界。
8. 完整 HTML 的自由度低于不受限网页，这是安全策略的有意选择。
9. Obsidian 风格支持仅覆盖课程阅读所需的提示框和重点标记，不兼容其插件、双链、嵌入、关系图谱或编辑功能。

## 24 风险与缓解

| 风险 | 影响 | 当前缓解 |
|---|---|---|
| Git 历史持续增长 | 克隆和构建变慢 | 压缩图片、避免重复附件、不提交构建产物 |
| 单课程文件过多 | 浏览器并发和磁盘压力 | 分批、限并发、失败重试 |
| Markdown 含危险 HTML | XSS | DOMPurify、CSP |
| 独立 HTML 含危险能力 | 安全风险 | 构建阶段白名单校验 |
| 公式写法不统一 | 渲染失败 | KaTeX 单引擎、示例内容、构建回归 |
| 提示框和高亮被过度使用 | 正文颜色过多、重点反而不清晰 | 提炼规范限定使用场景，普通内容继续使用正文与标题 |
| 将局部 Obsidian 语法误认为完整兼容 | 迁移笔记后部分语法不生效 | README、规范和界面只声明受支持子集 |
| 浏览器打印差异 | PDF 版式变化 | Chromium 为推荐环境、原生打印样式 |
| 网络或 Cloudflare 波动 | 访问失败 | GitHub 保留原文件、内容与平台解耦 |
| 免费加速线路失效或被替换 | 国内附件下载不稳定 | 基础名单、在线候选名单、本机实测、哈希校验和多线路故障切换 |
| 开着代理仍被固定分配镜像 | 绕路并降低下载速度 | 先检测 GitHub 直连能力，可直连时保持 Release 原地址 |
| AI 生成错误 | 错误知识传播 | 人工复核、PR 审查、保留版本历史 |

## 26 维护原则

每次迭代必须回答五个问题：

1. 是否仍然可以只通过修改 `content/` 发布课程？
2. 是否把不必要的计算、存储或并发压力放到了服务器？
3. 是否新增了可以被浏览器原生能力替代的依赖？
4. README、PRD 和实际代码是否仍然一致？
5. `content/自我介绍/` 中与本次功能相关的公开说明是否同步更新？

只要这四项保持成立，XU 就能继续作为一个低成本、易复制、可长期维护的开放知识平台。
