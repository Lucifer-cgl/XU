# 课件与 PDF 笔记提炼规范

本规范首先写给负责整理课程资料的 AI。开始读取、创建、补写或重构任何课程笔记前，AI 必须先完整阅读本文件，再读取目标课程的现有笔记和全部源资料。维护者也可以用它进行人工复核。

AI 默认只负责整理和修改笔记内容。完成后应停下来交给维护者检查；除非维护者在当前任务中明确要求，否则不要运行项目构建、创建 Git 提交、推送仓库或部署网站。

任务是把 PPT、PDF、Word、扫描讲义和课堂补充材料整理成 XU 可长期维护的 Markdown 笔记。本规范总结了现有财务管理、宏观经济学笔记中已经有效的做法，并借鉴 Obsidian 的提示框和重点标记习惯；目标不是逐页抄写课件，而是保留课程逻辑、公式含义、考试重点与可靠来源。

> [!important] 最低目标
> 读者即使不打开原课件，也能知道这一节讲了什么、公式中的每个符号是什么、结论在什么条件下成立，以及内容来自哪一页或哪一份资料。

## 一、开始整理前

先完整查看资料，不要读一页写一页。至少记录：

- 课程名称、章节和主题；
- 原文件名、资料类型和页码或幻灯片范围；
- 教师、作者或发布机构；不便公开姓名时使用统一匿名写法；
- 原始资料日期、当前整理日期和笔记版本；
- 是否有公开展示、引用或改编权限；
- 课件目录、反复出现的概念、公式、图表、例题和教师强调内容。

资料不完整、页面无法辨认或页码不确定时，应明确写“待核对”，不能让 AI 猜测。

## 二、文章开头的固定信息

每篇笔记只有一个一级标题。标题后建议先交代来源、范围和整理方式：

```markdown
# 第三章 资本成本

> [!summary] 来源与范围
> 根据《财务管理 A》第三章课件第 3—28 页整理；补充材料来自课程习题讲解。整理日期：2026-10-08。

> [!note] 整理原则
> 按“概念 → 公式 → 符号 → 适用条件 → 经济含义 → 例题 → 易错点”的顺序重组，未逐页照抄。
```

引用教师原话、教材定义或外部材料时，应标明来源。自己的归纳、AI 的补充解释与原文必须能区分。

## 三、标题和正文层级

- `#`：文章标题，只能出现一次；
- `##`：章节模块或一组完整问题；
- `###`：概念、模型、公式、例题或专题；
- `####`：必要的推导步骤或子问题，尽量少用；
- 不跳级，不用加粗文字假装标题；
- 每一节先给结论或问题，再展开解释，避免只有密集条目；
- 段落一次只表达一个中心意思，列表中的项目保持同一层级和语法。

## 四、术语和英文

课程材料中的英文不能原样堆放而不解释。

1. 第一次出现时写“中文名称（English full name，缩写）”；
2. 后文可以使用中文或缩写，但同一篇文章保持一致；
3. 图表坐标、模型变量和课件按钮等英文标签，应在正文或图注中翻译；
4. 有多个常见译名时，说明本文采用哪一种；
5. 只保留有助于理解或应试的英文原词，不为显得专业而增加术语。

例如：资本资产定价模型（Capital Asset Pricing Model，CAPM）。

## 五、通俗解释、重点和案例

笔记不能只给定义和公式。AI 在每个核心概念、指标、模型或方法后，应尽量回答下面的问题：

1. **它是什么**：先用一句不依赖专业术语的话说明本质，再给出严格定义；
2. **它有什么作用**：说明企业、管理者、投资者或分析者为什么需要它，通常用来支持什么判断；
3. **它反映了什么**：指标升降、结构变化或模型结果分别传递什么信息，不能只写“越高越好”；
4. **它在什么情况下会失真**：指出口径、行业、时间、一次性事项和假设条件带来的限制；
5. **它怎样用于现实决策**：结合定价、融资、投资、预算、库存、成本控制或绩效评价等具体场景；
6. **它与相近概念有什么区别**：用对比或反例消除最容易出现的误解。

> [!important] 每节真正需要留下的内容
> 至少让读者看见“核心结论、为什么重要、怎样使用、反映什么、容易错在哪里”。不能只有术语罗列，也不能用大段故事替代课程知识。

案例应尽量沿用课件、教材和课堂中的原案例，并保留来源。原资料没有案例时，可以编写简短的教学情境，但必须标明“假设案例”，不能虚构企业名称、真实事件、经营数据或教师观点。

一个有效案例通常按照下面的顺序展开：

```text
企业遇到的具体问题 → 可选择的方案 → 使用哪个概念或公式判断
→ 计算或推理过程 → 结果意味着什么 → 对企业决策的启示
```

例如，不要只写“经营杠杆反映经营风险”，还应说明：一家固定成本较高的企业在销量上升时利润可能增长更快，但销量下降时利润也会更快收缩；它帮助管理者判断成本结构对利润波动的放大程度。随后再给出公式、数字案例和适用条件。

为了让表达生动而不失真：

- 优先使用学生熟悉的企业经营场景，把抽象变量落到价格、销量、成本、现金和融资选择上；
- 数据简单但要带单位，前后口径一致；
- 案例结尾必须回到课程结论，说明“这个结果反映了什么”；
- 可以使用类比帮助入门，但类比后必须回到正式定义；
- 不为了热闹加入无关情节，不把相关关系写成因果关系；
- 重点内容使用 `[!important]`、`[!warning]` 或简短高亮，不能靠重复和堆砌颜色制造重点。

## 六、公式的完整写法

公式是财务管理与经济学笔记的重点。每个核心公式至少包含以下内容：

1. 公式本身；
2. 每个字母、上下标和单位的含义；
3. 成立的前提、口径和适用范围；
4. 经济或财务直觉；
5. 变量变化的方向关系；
6. 必要的推导，而不是无目的展开；
7. 一道带单位、过程和结论的例题；
8. 常见错误或容易混淆的公式；
9. 章末公式速查表。

```markdown
### 必要收益率

$$
r_i = r_f + \beta_i(r_m-r_f)
$$

- $r_i$：资产 $i$ 的必要收益率；
- $r_f$：无风险收益率；
- $\beta_i$：资产 $i$ 的系统性风险系数；
- $r_m-r_f$：市场风险溢价。

> [!warning] 适用口径
> 各收益率必须使用同一期间和同一名义或实际口径，不能把月度收益率与年度收益率直接代入同一个式子。

> [!failure] 常见错误
> 市场收益率 $r_m$ 不等于市场风险溢价 $r_m-r_f$。
```

可编辑的公式必须使用 LaTeX，不用公式截图代替。若原课件公式疑似有误，保留原式并明确标注“原课件写法”和“核对结果”，不要静默改写。

## 七、表格、图像和扫描页

### 表格

- 能重建的表格使用标准 Markdown 表格；
- 补全单位、时间、样本范围和口径；
- 合并单元格造成歧义时，改写为清晰的重复表头；
- 表后解释读者应观察什么，不只放一张数据表；
- 公式、普通段落和数据表不要用截图替代。

### 图像

图片按信息价值处理：

- 装饰图：删除；
- 纯文字截图：识别后改写为正文；
- 简单流程和关系：优先重建为列表、表格或可维护的文本结构；
- 必须保留的图表：提供有意义的替代文字、图注、来源、页码和许可；
- 图片中的关键趋势、坐标和结论必须在正文解释，不能让图片承担全部信息。

图片仍须遵守 XU 的外链与版权规则。Markdown 图片的标题会在阅读器中显示为图注：

```markdown
![横轴为产出、纵轴为价格水平的总需求曲线](https://raw.githubusercontent.com/用户名/仓库名/完整提交哈希/assets/ad-curve.webp "图 1 总需求曲线｜来源：课程课件第 18 页｜许可：经授权引用")

> 完整来源：https://example.com/source
```

## 八、重点、提示框和任务清单

XU 支持一组与 Obsidian 写法相近的提示框，但不承诺兼容 Obsidian 的全部语法。

```markdown
> [!summary] 本节摘要
> 用两三句话概括本节。

> [!important] 核心结论
> 写考试、推导或理解中最重要的结论。

> [!warning] 前提条件
> 写结论成立的限制和口径。

> [!failure] 易错点
> 写容易混淆的概念、符号或计算步骤。

> [!example] 例题
> 给出数据、计算过程、单位和结论。

> [!quote] 原文
> 保留必要的教师表述或教材定义，并写明页码。
```

`==重点高亮==` 只用于关键词、阈值、结论或容易漏看的限制，不能高亮整段。例如：==同一公式内的收益率口径必须一致==。普通补充使用 `[!note]`，待办事项使用 `- [ ]`；完成核对后可改为 `- [x]`。

> [!tip] 克制使用
> 一屏出现太多颜色反而会削弱重点。只有确实需要从正文中跳出的信息才使用提示框或高亮。

## 九、例题和答案

- 题干保留所有数据、单位和必要条件；
- 先写所求问题，再写公式、代入、计算和结论；
- 中间数值的保留位数与最终答案的取整规则要说明；
- 不只给答案，要指出为什么采用这个公式；
- 多种解法并存时说明各自适用条件；
- 原题存在歧义时先指出歧义，再给出合理假设下的解答。

## 十、来源、版权与 AI 边界

笔记必须能追溯到原资料：

- 文章开头写总体来源和范围；
- 关键定义、数据、原话和图表尽量写页码或幻灯片编号；
- 文末列出使用过的课件、教材、公开网页和补充资料；
- 直接引用、转述、个人归纳和 AI 补充要能区分；
- AI 不得捏造来源、页码、教师观点、数据或许可证；
- 无法确认版权时只提供原始页面链接，不复制完整材料；
- 最终内容必须由能理解课程的人复核，AI 输出不能直接视为正确答案。

## 十一、人工与 AI 的推荐流程

1. 浏览全部源文件，建立资料清单；
2. 提取原目录、学习目标、核心概念、公式、图表和例题；
3. 按课程逻辑重新拟定标题层级；
4. 先写正文骨架，再补充公式解释、直觉、例题和易错点；
5. 对照原资料逐项核验数字、符号、单位、页码和来源；
6. 检查术语第一次出现时是否给出中英文；
7. 检查图片是否真的必要，图注和许可是否完整；
8. 在原文件中检查标题层级、公式语法、表格、图片说明和来源记录；
9. 列出仍需确认的问题，由人工进行最后的课程知识与版权复核。

给 AI 开始任务时，可以使用下面的指令：

```text
先完整阅读本规范和目标课程现有笔记，再查看全部课件或 PDF。
不要逐页照抄，也不要发明原资料没有的事实、页码或来源。
沿用课程现有术语和结构；每个核心公式解释全部符号、单位、前提、直觉和易错点。
每个核心概念先用通俗语言解释它是什么，再说明它有什么作用、在企业中怎样使用、结果反映什么和什么时候可能失真。
优先讲清原课件案例；需要补充时只能编写明确标为“假设案例”的教学情境，并在结尾回到课程结论。
英文首次出现时给出中文、英文全称和缩写；表格尽量重建，必要图片提供替代文字、图注、来源与许可。
完成后列出无法确认的内容并停止。不要自行运行构建、提交、推送或部署。
```

## 十二、交付检查清单

- [ ] 只有一个一级标题，标题层级没有跳级；
- [ ] 来源、资料范围、页码和整理日期已说明；
- [ ] 核心概念不是课件文字的机械堆叠；
- [ ] 核心概念说明了它是什么、有什么作用、在企业中怎样使用以及结果反映什么；
- [ ] 重点内容清楚可见，但没有用重复、颜色或提示框过度强调；
- [ ] 案例包含问题、判断过程、结果和启示；补充案例已明确标为“假设案例”；
- [ ] 每个核心公式的符号、单位、前提和直觉都已解释；
- [ ] 英文术语第一次出现时有中文解释；
- [ ] 表格可搜索，图片有替代文字、图注、来源和许可；
- [ ] 重点提示克制，易错点和例题足够清楚；
- [ ] 没有把 AI 猜测写成课程事实；
- [ ] 已在原文件中检查标题层级、公式语法、表格、图片说明和来源记录；
- [ ] 已列出仍需人工确认的内容，未自行构建、提交、推送或部署。
